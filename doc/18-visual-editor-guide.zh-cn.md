# 18 可视化编辑器使用说明

适用版本：插件 **0.10.0**，匹配播放器 **v0.10.0**（story 8 / UI 3 / save 9）。本文覆盖日常创作最常用的工作台、UI 编辑器、事件、幕 ID、工程设置和试玩流程；完整的 XML/JS 契约仍以引擎源码和 [04 当前引擎 API](04-current-engine-api.zh-cn.md) 为准。

> 编辑器读写的是实际工程中的 XML、JS 和资源文件。界面操作会直接保存到对应文件，并进入 VS Code 的撤销历史；“可视化”不是另一份独立的游戏数据。

## 1. 打开工程

1. 在命令面板执行 **Kakera：新建游戏工程**，选择空文件夹；编辑器会生成最小 story/UI 内容。
2. 打开已有工程时执行 **Kakera：打开故事工作台**，或在工程根目录找到 `project.kakera-editor.json`。
3. 第一次使用先在“准备工具”中配置匹配的 v0.10.0 播放器目录；VSIX 已附带工具时可直接试玩。
4. 工作区未受信任时界面只读，保存、试玩、构建和工具执行会被限制。

### 识别工程

工程根目录需要 `project.kakera-editor.json` 和游戏内容。常见文件：

| 文件 | 用途 |
| --- | --- |
| `story.xml` / 章节 XML | 幕、台词、人物、画面和入口 |
| `scripts/*.js` | 推进、选择、结束、生命周期和 UI 事件 |
| `ui.xml` / `ui/**` | UI 页面、控件、变量和演出 |
| `assets/**` | 图片、音频、视频和字体 |
| `.editor/workbench.json` | 编辑器自己的分镜位置和图集预设，不进入游戏包 |

## 2. 故事工作台

### VS Code 原生工程侧栏

Activity Bar 的 Kakera 视图是 VS Code 原生 TreeView，跟随当前颜色主题、图标主题和字体，不使用 Webview 模拟：

- **人物**：新建人物、导入立绘或 Live2D；人物条目右键可重命名/删除/继续导入。仍被立绘引用的人物拒绝删除。
- **美术资源 / 音频与字体**：导入资源或 CG，条目右键查看已知画面/音频引用。
- **剧本**：按 XML 文件分组，展开后列出该文件的实际幕；点击幕会打开/聚焦可视化编辑器并直接选中该幕。右键幕可新建后续幕、删除或在编辑器中定位；分类菜单可打开分镜或完整校验。
- **变量**：分类右键新建变量；条目右键编辑初始值/int 范围或删除。
- **JS 程序**：点击/右键打开声明的脚本源码。
- **界面**：打开 UI 编辑器。
- 视图标题栏可刷新；打开工程、切换工程以及编辑文档/文件变化后会自动更新分类计数。

右键菜单的删除/新建都走后台校验、保存和宿主撤销链；失败会在通知中说明，不会只改侧栏显示。

编辑器自动生成的所有稳定 ID 使用 8 字节随机数的 16 位十六进制短格式，例如 `7f3c9a12b45d8e60`：包括幕、人物、立绘/模型资源、导入资源、visual/外观、UI 页面/控件、点九/图集和图片工具示例控件。生成器会在对应命名空间检查冲突，连续 64 次冲突后才回退 UUID。已有工程中的手写或旧 ID 不会被批量改写。

顶部应用栏显示工程名、当前幕和常用操作。左侧是幕列表，中间是舞台/分镜关系图，右侧是当前幕检查器，底部状态栏显示保存、只读和引擎状态。

### 选择、搜索与保存

- 左侧点击幕切换编辑；搜索框按台词或引用名过滤。
- 右侧修改台词、说话人、完整画面、音频、路由或生命周期后，点击 **保存幕**。
- **还原编辑**丢弃当前草稿并重新读取源码。
- 切换幕、打开工程设置或离开工作台前若有未保存草稿，编辑器会先提示。
- 源码被外部修改时，草稿保留并显示冲突提示；不会在未确认时覆盖新源码。

### 流程图多选与快捷键

关系图支持常用编辑快捷键；输入框、下拉框和 contenteditable 内的原生选择/撤销行为不会被拦截：

- `Ctrl/⌘+A` 全选实际幕并显示选中数量；`Ctrl/⌘` 单击追加/移除，`Shift` 单击从当前幕扩展范围。
- `方向键`、`Home`、`End` 切换当前幕；`Shift+方向键` 扩展多选。
- 多选后拖动任一已选幕会整体移动；`Alt+方向键` 整体微调 20px，松手/按键后一次保存到 `.editor/workbench.json`。
- `Delete` / `Backspace` 批量删除；`Ctrl/⌘+D` 复制选中幕；`Ctrl/⌘+C` 记录选中幕，`Ctrl/⌘+V` 在当前幕之后粘贴副本；复制内容只保留在当前工作台内，不写系统剪贴板；`Ctrl/⌘+F` 聚焦搜索；`Ctrl/⌘+S` 保存当前幕草稿。
- `Esc` 先取消连线、拖动或平移；没有进行中的手势时，把多选收起到当前幕。
- 批量删除仍要求至少保留一幕，并检查每条入边、入口和生命周期引用；无法证明的入边保留“待连接”占位，不替作者选择分支。批量复制/删除走一次源事务与宿主撤销链。

### 新建、复制、排序和删除

- **＋新增幕**：在当前幕之后插入一个合法新幕，保留原有后续。
- **复制幕**：复制当前幕并生成新的稳定 ID；布局和路由按当前幕的设定处理。
- **前移/后移**：只改变同一 story 文件中的幕顺序，不自动改剧情连接。
- **删除幕**：有明确后续时会重连；无法证明的入边会阻止删除。至少保留一个实际幕。
- 未连接的可视路线会显示“待连接”节点；编辑器会生成合法 End 占位，不会伪造空目标。发布前必须补齐。

### 编辑剧情路由

在“剧情路由”区域选择：

- **推进到下一幕**：设置后续幕、条件和变量更新。
- **显示选择**：为每个选项设置文字、显示条件和目标；选项 ID 用于稳定对应。
- **结束**：没有后续目标。
- **按变量条件分流**：用类型化比较和“满足/不满足”分支设置多个出口；默认出口必须明确。

拖出连接点或拖动箭头端点可以重新连线；**断开所选连线**会保留合法待连接占位。关系图支持拖动幕卡、缩放、重置和 **自动排列**；拖动幕卡会写入 `.editor/workbench.json`，不改剧情。

**平移画布**：在流程图的空白背景按住鼠标/触控笔拖动，可左右上下移动视口；这不会移动幕卡，也不会保存布局。幕卡、连接点和边缘线优先响应各自的点击/拖动手势；按 `Esc` 可取消正在进行的手势。

### 变量编辑与删除

工作台左侧“变量”卡片列出当前故事变量：

- **编辑** 可修改初始值；int 还可修改下限/上限，必须保持 i64 范围且初始值在范围内。变量 ID 和类型创建后固定，避免静默破坏脚本、条件和绑定。
- **删除** 移除整个变量声明；仍被已识别路线条件或更新引用时会拒绝，先修改相关路线。JS/动态引用由真实引擎校验，失败不会落盘。
- 变量修改只改原 XML 范围，保留注释、其他变量和文件格式；仍走 revision、WorkspaceEdit、撤销和保存链。

### 多起始幕

故事检查器的 **故事起点** 管理 `story.entry`：

- **加入起始幕** 把当前幕追加到列表；**设为唯一入口** 只保留当前幕；标签上的 `×` 移除一个起点，但至少保留一个。
- `story.entry` 使用空白分隔的 ID/name。关系图把每个起点都作为独立的可达根，并给卡片显示“入口”；列表第一项**不会**自动成为运行入口。
- 播放器启动时只显示 XML 初始 UI，等待 UI 事件显式选择起点或读档。未选择时没有当前幕、剧情进入回调、剧情音频、自动档和已读；编辑器试玩也会停在初始界面。
- 删除入口幕会从列表中移除该项；若删掉最后一个起点，编辑器选择后继/其他幕补位。重命名入口幕只更新列表中的对应项，保留其他起点。
- 起点可以不在同一剧情分支，也可以指向不同变量/画面；引擎会逐个验证起点初始选项、`game.enter` 计划、立绘和模型命令。
- 新建模板默认是单入口，初始 HUD 的“开始故事”按钮调用无参 `ctx.restart()`。加入第二个起点后要把开始按钮/菜单改为 `ctx.restart("入口")` 或 `ctx.resume("入口")`；多起点无参 restart 会被播放器拒绝。

### 修改幕 ID

右侧“幕标识”区域的 **幕 ID** 可以修改当前幕的 XML ID/引用名。点击 **重命名幕** 后会：

- 更新当前 `<frame>` 的 ID（若有 `name` 也同步）；
- 更新故事入口、已识别的推进/选项目标、连接关系；
- 保留源码中的其他内容和注释。
- 如果检测到 `on.frameEnter/Exit`、`ctx.resume` 或其他生命周期引用，会拒绝并在源码中先处理；编辑器不会猜测性改写未识别回调。

以下情况会拒绝重命名，避免留下悬空目标：

- 存在动态注册、无法证明的路线或未知目标；
- 该幕仍被 `on.frameEnter/Exit`、`ctx.resume` 等生命周期/交接引用；
- 新 ID 已存在或包含空格、引号、斜杠等不支持的字符。

先处理源码中的动态/生命周期引用，再回到工作台重命名。重命名不会自动迁移分镜手动位置。

### 页面/末幕生命周期

选中幕或 UI 页面后可设置“打开页面”的离幕/关页动作。末幕文字完成后的手动继续会触发一次 `frameExit`；补全文字不触发，自动播放和 Ctrl 在结尾停止。生命周期表单只写单条固定 `ctx.open`/`ctx.resume`，自定义回调请直接在源码维护。

## 3. UI 编辑器

从顶部 **UI** 或命令面板打开。左侧是页面与控件层级，中间是设计画布，右侧是页面/控件属性。

### 页面

- **＋新增页面**：选择声明的 UI 文件，输入页面标识；留空自动生成。
- 页面属性可设置是否模态、是否暂停剧情、页面进入演出、背景点击事件。
- **画布与入口**：调整 16:9 画布尺寸和初始非模态页面。
- 页面结束后的关闭动作在“页面结束后（关闭时）”设置：
  - **从指定幕开始 / 续接**：写入 `ctx.resume("幕")`；
  - **从隐藏槽恢复**：写入 `ctx.resume()`。

### 控件与画布

- 在“添加控件”选择十类控件（场景、面板、图片、点九、文本、按钮、滑条、开关、列表模板、HSV 选色器），选择父容器/资源/事件后添加。
- 点击控件选中，拖动移动，拖动右下角手柄调整大小；8px 吸附可关闭。
- 用工具栏的“− / ＋ / 适合常用窗口”缩放画布；键盘方向键微调选中控件，`Shift` 加速，`Esc` 取消拖动。
- 右侧属性按“布局与外观 / 内容与资源 / 交互与数据”分组；标有绑定的字段连接 UI 变量，不是写死文本。
- **复制控件**保留结构并生成新 ID；删除前确认无必须依赖。
- 场景控件只是剧情画面占位，视频、随机音效等请用播放器试玩确认。

### 创建、修改和删除事件

在左侧“交互事件”中：

1. 点击 **＋新建事件**，输入事件名并选择动作。
2. 给按钮/滑条/开关选择该事件，或设置页面背景点击事件。
3. 已有事件行显示 **编辑** 和 **删除**：
   - **编辑**会预填原动作、目标、起始幕和先打开页面选项；保存时替换该事件的固定回调。
   - 修改事件名会同步更新引用它的控件和页面背景事件。
   - **删除**仅允许删除未被引用的简单事件；仍有控件或背景引用时先改掉引用。
   - 手写、带注释、带自定义语句/条件/循环的回调会标记“源码维护”，不能可视化改写或删除。

支持的常见动作包括打开/关闭页面、推进/重开、选择列表项、设置项、UI 声音开关、演出/音效、`present` 交接，以及 **开始 / 恢复剧情**。

### 从 UI 开始或恢复剧情

选择动作 **开始 / 恢复剧情（可指定起始幕）**：

- 指定“起始幕”：写入 `ctx.resume("幕")`；
- 可选“先打开页面”：写入 `ctx.open("页面"); ctx.resume("幕")`；
- 留空起始幕：写入 `ctx.resume()`，由播放器读取隐藏槽 continuation。

首次显式选择以初始变量和单条起点历史建立会话；剧情开始后指定的 resume 才沿用隐藏 continuation 的变量/历史。它不清理剧情变量，不是 `ctx.restart`。首次没有隐藏槽且未指定幕时，匹配播放器会拒绝；编辑器不会创建或修改隐藏槽。

选择动作 **重新开始（可指定起始幕）**：

- 指定“起始幕”：写入 `ctx.restart("幕")`，建立新会话并恢复初始变量/历史；
- 可选“先打开页面”：写入 `ctx.open("页面"); ctx.restart("幕")`，适合从标题页进入 HUD；
- 多起始幕项目必须选择目标；单起始幕可留空写 `ctx.restart()`。
- 目标必须是“故事起点”中声明的幕；编辑器保存时会校验，播放器运行时会再次校验。

### 快捷弹窗、玩家快捷键与 HSV 配色

**快捷弹窗**：在左侧页面树点击 **＋快捷弹窗**，选择写入的 UI 文件，填写页面 ID（可留空）、标题、正文及确认/取消文字。确认动作选择“关闭当前页面”“调用已注册事件”或“退出游戏”：
- “退出游戏”会自动追加一个 `ctx.quit()` 的普通 `on.ui` 事件；
- 取消按钮始终 `route="close"`，不删除已打开页面以下的页面；
- 生成后仍可在属性检查器改文字、绑定、颜色和尺寸；工具不会自动添加打开弹窗的按钮，需要自己用 `route="open:页面"` 或事件接入。
- `ctx.quit()` 只关闭播放器窗口，不保存新槽、不触发幕/页面退出回调。

**玩家快捷键**：先准备 UI string 变量（如 `shortcutAdvanceDraft`）和显示 `shortcuts.advanceLabel` 等绑定的文本。事件向导中：
1. 用“捕获键盘快捷键”选择动作（前进/快进/跳过演出）和已注册的结果事件；结果事件的 `ctx.value` 是捕获到的规范绑定。
2. 在结果事件或作者 JS 中把值存入草稿 UI string；草稿页的“应用”按钮再用“修改快捷键绑定”写入 `ctx.keybinding(动作, 绑定)`，留空绑定表示写 `null` 禁用。
3. “恢复默认快捷键”单独写 `ctx.resetKeybindings()`；捕获进行中可用“取消快捷键捕获”写 `ctx.cancelShortcutCapture()`。
- 绑定必须是文档 token（如 `Enter`、`Ctrl+KeyK`），按 Ctrl、Alt、Shift 顺序规范化；Escape、Meta、Ctrl+Alt 和系统组合会被拒绝。跨动作冲突和释放屏障由播放器最终校验。
- 编辑器不写 `keybindings.json`，也不在画布中模拟真实按键；`shortcuts.*` 在画布按默认绑定显示示例。

**HSV 选色器与配色槽位**：
1. 先新建 UI string 变量，初始值写成合法颜色（如 `#10253BFF`）。
2. 在“配色槽位”新增根级 `palette` 槽位（如 `dialogue_background`），输入初值；槽位 ID 创建后固定。
3. “添加控件”选择“HSV 选色器”，绑定颜色值和已注册事件；可设置是否显示透明条。控件要求 128×224 以上、最多 8 个且不能放入列表模板。
4. 控件事件只收到候选 `#RRGGBBAA`；在作者 JS/结果事件中用 `ctx.setUi(...)` 才更新数值。事件向导的“保存颜色覆盖”“恢复作者默认配色”写 `ctx.colorPreference(槽位[, null])` / `ctx.resetColors()`，编辑器不创建或修改 `ui-colors.json`。
5. 普通控件的 `color` 属性可用“HSV 色盘”按钮打开色相环编辑；也可以改用“颜色绑定”选择 `ui.字符串` 或 `colors.槽位`，两者不能同时设置。文字、按钮、点九等精确运行效果以匹配播放器为准。

### UI 变量、演出与源码

- **＋新增 UI 变量**支持 bool/int/string；int 保留 i64 十进制边界，不先转 Number。
- **演出与音效**可编辑 UI 序列（淡入淡出、视频、音效）和带权音效组；页面进入演出、按钮点击音效和玩家声音偏好各自独立。
- **查看 UI 源码**打开实际 XML/JS；源码是事实来源。画布只显示静态布局，不执行 JS、动画、媒体或隐藏交接。

## 4. CG 资源与画廊

CG 是独立于普通 image 的 `cg` 资源类型，不是“任意背景图”。创建方式：

1. 点击顶部 **导入 CG** 按钮，或执行 **Kakera：导入 CG 专用资源**；
2. 选择 PNG/JPEG，填写稳定资源 ID（如 `cg.promise`）和授权来源；
3. 资源会写入 `<assets><cg id="cg.promise" src="assets/imported/..."/></assets>`。

### 让一幕显示 CG

在故事检查器“画面”区域选择 **CG 专用画面**，保存后生成 `<visual id="..." cg="cg.promise"/>` 并把当前幕指向它。CG 画面显示完整图片、不叠加人物；CG 与背景/三槽立绘互斥。舞台预览显示 CG，若想替换回普通画面，在“CG 专用画面”选择“不使用 CG”，再选择背景/人物并保存。

不能把人物外观“放入”CG 场景；如需人物与背景，请切换到普通完整画面。

### 画廊标题与初始解锁

播放器会自动把每个 `<cg>` 加入画廊，默认标题是资源 ID、默认未解锁。UI 编辑器左侧 **CG 画廊**：

- 自动条目显示“自动”；
- 点击 **编辑** 可写中文标题和“初始解锁”；保存后写显式 `<gallery><cg .../></gallery>`；
- 显式条目可 **移除**，之后恢复为自动默认条目；
- 专用 CG 的画廊 ID 必须等于资源 ID；普通 image 收藏项可以自定义 ID；
- 初始解锁只影响默认状态；玩家个人 `profile.json` 中的共享解锁由播放器维护。

### 解锁和绑定

事件向导动作 **解锁 CG**：

- 不选目标：`ctx.unlock(ctx.game.cgId);`，适合进入 CG 幕的 `game.enter`；
- 选择目标：`ctx.unlock("cg.promise");`。

“game.enter”是作者的既有回调，编辑器不会另建重复注册；请在现有回调中加入：

```javascript
if (ctx.game.cgId) ctx.unlock(ctx.game.cgId);
```

UI 绑定建议包含：

| 绑定 | 类型 | 含义 |
| --- | --- | --- |
| `game.cgId` | 文字 | 当前幕专用 CG ID；普通幕为空 |
| `cg.total` | 数值 | 画廊条目总数（含普通 image 收藏项） |
| `cg.unlocked` | 数值 | 已解锁数量 |
| `cg.progress` | 文字 | 如“已解锁 1 / 3” |

加载/显示 CG **不会自动解锁**；解锁时机、共享 profile 原子写和读档不撤销由匹配播放器负责。编辑器不写 `profile.json`，也不在画布中执行解锁。

## 5. 工程设置与图片工具

顶部 **工程** 抽屉包含：

- 游戏标题（写入 UI title/绑定变量初始值）；
- 人物名称与稳定 ID；
- 人物外观/立绘/Live2D 库；
- 工具目录和引擎版本状态。

顶部 **图片** 抽屉用于导入图片、运行点九生成、查看图集区域预设。图片应用会写真实 UI image/region，密度只属于 nine-patch；不会把区域预设当游戏剧情。

## 6. 试玩、调试和构建

- **试玩**：从入口启动匹配版本播放器，使用独立临时存档目录，不会污染玩家手动槽。
- **调试**：DAP 接入真实播放器；支持 XML 幕断点、当前/候选只读变量、暂停/继续、推进和选项选择。不提供 JS 行级步进、任意跳转或变量写入。
- **构建**：使用匹配 `kakera-pack` 和 v0.10.0 依赖选择，生成独立发行目录；额外文件只按 `kakera.package.json` 清单进入。发布前检查 KPAK 全包、许可证和源码外运行。

## 7. 保存、撤销与冲突

- 日常编辑直接保存当前文件，不需要“应用差异”确认；可立即使用 VS Code 撤销/重做。
- 修改已打开文件使用 VS Code 的 WorkspaceEdit，未保存缓冲优先于磁盘；试玩/构建读取冻结代次。
- 外部修改导致 revision 改变时，界面保留草稿并提示载入最新源码；不会静默覆盖。
- `.editor/workbench.json`、`flow-checkpoint.json`、玩家槽位、`ui-audio.json` 等不是剧情源文件；其中后三者不进入发行包。
- 发生错误时先看顶部错误条和“查看源码”；修复 XML/JS 后界面会刷新，不会重放未完成的写操作。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| 删除事件按钮不可用 | 仍有控件/页面背景引用，或事件是手写/自定义回调；先改引用或直接编辑源码 |
| 重命名幕被拒绝 | 存在动态路线、生命周期/`ctx.resume` 引用或目标 ID 冲突；先处理源码中的引用 |
| UI 画布拖动没有保存 | 检查是否在只读/冲突状态；等待宿主重绘后松手会由窗口级 pointerup 提交 |
| 保存后仍未变化 | 检查错误条、文件后缀和工程是否指向另一个目录；必要时刷新或重新打开工作台 |
| 试玩提示工具不匹配 | 用 **准备工具** 选择 v0.10.0 release 工具目录，确认 `tools.json` 哈希和版本 |
| 画布和播放器不一致 | 画布是静态设计预览；媒体、动画、随机和隐藏交接请在真实播放器验证 |
| 试玩停在标题/初始 UI | 多起始幕（以及单入口的新契约）不自动进入剧情；从 UI 的起点按钮调用 `ctx.resume("入口")` 或 `ctx.restart("入口")`，或载入存档 |
| 多起始幕无参重新开始被拒绝 | “重新开始”动作必须选择“故事起点”中的幕；先加入起点，再在事件向导里选择 |
| 导入 CG 后舞台仍是普通画面 | 需要在“画面”区域选择“CG 专用画面”并保存；导入资源本身不会改当前幕 |
| 解锁 CG 后进度不变 | 解锁需要作者回调调用 `ctx.unlock`；加载/显示 CG 不会自动解锁，共享进度在独立 profile.json |

## 9. 键盘与可访问性

- `Esc`：关闭抽屉、取消画布拖动/连线/平移，或把流程图多选收起到当前幕；不会误删内容。
- 流程图：`Ctrl/⌘+A` 全选，`Ctrl/⌘`/`Shift` 单击多选，方向键/`Home`/`End` 切换，`Shift+方向键` 扩展，`Alt+方向键` 批量微调，`Delete`/`Backspace` 删除，`Ctrl/⌘+D`/`C`/`V` 复制粘贴，`Ctrl/⌘+F` 搜索，`Ctrl/⌘+S` 保存草稿。
- 方向键：在 UI 画布移动选中控件；`Shift` + 方向键按 8px 步进。
- 生命周期/控件选择使用原生下拉框，保留可读标签；只读时控件明确禁用。输入框内保留浏览器/VS Code 原生快捷键。
- 界面支持 VS Code 浅色/深色主题和窄窗口单列布局；窄屏仍保留页面、控件和属性入口。

更细的 UI 字段与源码写入规则见 [16 UI 编辑器](16-ui-editor.zh-cn.md)，事件与生命周期的静态映射见 [13 JS/XML 实时映射](13-live-logic-mapping.zh-cn.md)。
