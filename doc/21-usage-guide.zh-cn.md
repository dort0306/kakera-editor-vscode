# 21 使用说明：安装、工作台与工具

本文件承接根 README 迁出的操作说明。根 README 只保留项目简介、构建与测试方法及许可证；可视化编辑器的完整入口与常见问题见 [18 可视化编辑器使用说明](18-visual-editor-guide.zh-cn.md)，UI 控件/事件写入规则见 [16 UI 编辑器](16-ui-editor.zh-cn.md)，条件分流见 [15](15-variable-conditional-routes.zh-cn.md)，点九与图集见 [14](14-graph-and-texture-tools.zh-cn.md)，JS/XML 映射见 [13](13-live-logic-mapping.zh-cn.md)，游戏本地化见 [19](19-localization.zh-cn.md)，与上游引擎同步的契约细节见 [22 引擎同步与版本增量](22-engine-sync-notes.zh-cn.md)，能力状态见 [20](20-capabilities-status.zh-cn.md)。

更新：2026-10-31，插件 0.11.2。

## 1. 安装与启动

在 VS Code 命令面板执行 **Extensions: Install from VSIX...**，选择生成的 `artifacts/kakera-editor-vscode-0.11.2.vsix`。当前预览包包含经过 SHA-256 核验的 v0.11.2 播放器、打包器和 Noto CJK 字体，不需要 Rust 或 AI 服务；安装后扩展 ID 为 `dort0306.kakera-editor-vscode@0.11.2`。

1. 执行 **Kakera：打开创作首页**，新建工程或打开已有内容根；如果 VS Code 还没有打开文件夹，也可以直接在资源管理器的空状态点击“打开 Kakera 工程目录”。
2. 在分镜中选择一幕，编辑台词、说话人、画面、音频与路由。
3. 点击“保存幕”直接保存；新增、删除幕也直接处理并保存，不要求查看或理解源码。后台仍进行引擎检查和冲突检查，支持宿主撤销/重做。
4. 点击“试玩”启动独立播放器；多起始幕项目在初始 UI 选择起点或读档后才能进入剧情。“停止”仅关闭本插件启动的试玩。
5. 点击“调试”，使用 XML frame 断点和变量视图；在命令面板执行 **Kakera：调试时选择选项**。
6. 点击“构建”，选择内容根之外的发行父目录，审阅实际包内文件后生成独立游戏目录。

在工作台顶部的 **游戏设置 → 标题** 编辑游戏名称；它会同时显示在工作台和播放器窗口中，不修改存档标识。已有 `title-bind` 的工程默认修改绑定变量初始值；需要固定标题时勾选解除绑定。

在 **游戏设置 → 人物** 创建或改名，使用“批量导入立绘”选择多张 PNG/JPEG；或导入 `.model3.json`，一起收集模型声明的贴图、动作、表情等依赖并选择静态回退图。也可从已有资源批量关联。选择人物外观和左/中/右位置后，点击“将此外观放入当前幕”；原背景和其他人物会保留。

## 2. 分镜工作台

### 2.1 分支视图与文件顺序

分镜默认显示 **分支视图**：不同分支用不同颜色，后续幕沿同一水平行延伸，汇合到同一幕时共用节点，自循环显示回线；高级 JS 的未知目标不会推测为下一幕。点击卡片继续编辑，可缩放/滚动查看。需要整理源文件顺序时切换“文件顺序”。

### 2.2 拖动与连线

拖动幕卡片后松手，自动吸附并保存布局；“自动排列”恢复默认分支布局，不改变剧情。可拖出幕右侧的连接点，或拖动箭头端点，落到目标幕上重新连接；每个选项有独立连接点。也可点击连接点和目标，或用 Tab/Enter 操作；Alt+方向键移动幕。点击连线后可“断开所选连线”，原选项、条件和变量更新会保留。Escape/无效落点取消；有未保存编辑时先保存或还原。

### 2.3 选择与快捷键

关系图支持 `Ctrl/⌘+A` 全选实际幕；`Ctrl/⌘` 单击追加/移除、`Shift` 单击范围选择，方向键/`Home`/`End` 切换当前幕，`Shift+方向键` 扩展选择。多选后可一起拖动或用 `Alt+方向键` 微调，松手一次保存布局；`Delete/Backspace` 批量删除，`Ctrl+D` 复制，`Ctrl+C/V` 在当前工作台内复制并在当前幕后粘贴副本（不写系统剪贴板），`Ctrl+F` 聚焦搜索，`Ctrl+S` 保存当前幕草稿，`Esc` 取消手势或收起到当前幕。多幕删除/复制仍逐一校验可编辑路线和生命周期引用，无法证明的入边保留待连接。

### 2.4 流程图背景平移（0.8.5）

关系图空白背景可直接拖动平移画布（滚动容器），不移动幕卡、不触发布局保存；幕卡拖动、连线、缩放、点击与只读查看保持独立。工具栏会提示“拖动空白处平移画布”。

### 2.5 新增与删除幕

选中普通幕点击“新增幕”，新幕会插入它后面并接回原后续；选中结束幕则继续向后创作。选项幕按显示顺序填入第一个未连接选项，已连接的分支保持不变；全部连接后需先增加选项，或选择分支上的幕继续新增。新建后会自动选中新幕。

删除普通中间幕会接回明确的后续；删除结束幕或分支幕时，无法确定的入口保留为“待连接”，不删除其他幕或替作者选择路线。故事至少保留一幕；入口可在故事检查器的“故事起点”中增删或设为唯一入口。新建、删除和普通保存不弹出源码确认，只保存本次涉及的文件。撤销/重做恢复编辑缓冲后可用 VS Code 保存；恢复记录保留变更前后内容。

### 2.6 待连接占位与构建阻止

未连接选项可保存并继续编辑，图中显示待连接节点；补幕后自动清理内部占位。尚未连接的路线必须补齐后才能通过插件构建正式游戏。

### 2.7 变量条件分流

先在“变量”中创建 bool/int/string 变量，选择一幕并在“剧情路由 → 推进到下一幕”下点击“按变量条件分流”。设置条件变量、比较方式、满足时进入的幕，以及“否则进入”的默认幕。bool 使用 true/false 下拉；int 可用大小比较或“介于（含边界）”，支持且/或组合和条件上下移。运行时先执行本线路的变量更新，再按顺序选第一个满足的条件；都不满足时走默认线路。选项也可在选中后按条件分流，选项显示条件单独设置。点击“保存幕”直接验证并保存，分支图为各条件及默认出口分色，拖线只修改选中的出口。详见[条件分流说明](15-variable-conditional-routes.zh-cn.md)。

### 2.8 导出流程图

在分支视图点击“导出流程图”，选择保存位置和 SVG/HTML 文件类型。SVG 可缩放，悬停幕/连线查看全文；HTML 包含流程图及完整台词、选项、条件和变量更新清单，支持浏览器 Ctrl+F 查找和幕间跳转。两者保留手动布局和分支颜色，标明待连接/未知目标/未接入入口，不受当前搜索、缩放或滚动范围限制。导出读取当前源码缓冲，不修改游戏；表单草稿需先保存或还原。

### 2.9 多起始幕（0.8.6）

`story.entry` 支持空白分隔的多个 ID/name；故事检查器的“故事起点”可加入/移除起点、设为唯一入口，关系图把每个起点作为独立根并显示“入口”标记。播放器启动只显示初始 UI，不自动进入第一项；UI 事件向导可用 `ctx.restart("入口")`、`ctx.resume("入口")`，并可先打开 HUD/标题页（生成 `ctx.open(...); ctx.restart(...)`）。调试状态识别 `game_started=false` 和空 `frame_id`，等待玩家从 UI 选线或读档。

### 2.10 事件与幕 ID 管理（0.8.3）

已有 UI 事件可查看动作、编辑名称/目标/起始幕并重新保存，也可删除未引用的简单事件；改名会同步更新控件与页面背景引用。故事检查器的“幕 ID”可手动重命名当前幕，更新入口、已识别的推进/选项目标和连接；存在动态路线或生命周期引用时会拒绝，避免留下悬空目标。完整操作见 [可视化编辑器使用说明](18-visual-editor-guide.zh-cn.md)。

### 2.11 变量与入口修复（0.8.7）

工作台变量列表可编辑初始值/i64 下限上限并删除变量；变量 ID/类型创建后固定，删除仍被路线条件或更新引用的变量会拒绝。“加入起始幕”不再错误地要求当前幕引用，只按提交的起点列表校验。

### 2.12 幕与页面生命周期（0.7.0）

已声明脚本中的 `frame(id).enter/exit`、`ui("页面").bind("screen.open"/"screen.close", …)` 会作为源码事实参与静态映射与源码导航，但不会变成剧情连线；动态或缺失目标会给出诊断。`ctx.present` 的页面引用按入口及 include 当前缓冲检查，在分镜工作台和 UI 编辑器提示脚本文件/行号；动态页面目标标为不确定，修正源码后重新检查。删除仍被生命周期回调或 `ctx.resume` 目标引用的幕、或被 `ui(页面).bind`/`ctx.present` 引用的页面会被阻止。事件向导可追加 `ctx.present(页面)` 和 `ctx.resume()`/`ctx.resume(幕)`；画布不执行交接、隐藏槽或演出，运行效果以真实播放器为准。

### 2.13 可视编辑结束后动作

选中幕，在属性底部的“幕结束后（离开时）”选择“打开页面”和目标；选择 UI 页面的“页面属性”，在“页面结束后（关闭时）”选择“续接指定幕”“恢复待续剧情”或“打开页面”。点击“保存结束后动作”后台校验并保存；改为“不添加动作”可移除已识别的简单动作，支持撤销/重做。复杂手写生命周期保持源码控制。幕侧保留原正常后续，不修改剧情路由；结束幕不会凭空触发离幕。演出自动结束要执行关页动作时，将演出结束行为设为 `close`；普通页面可用关闭按钮结束。

### 2.14 从 UI 显式开始/恢复剧情（0.8.2 / 引擎 v0.9.1）

在 UI 编辑器的“新建事件”选择“开始 / 恢复剧情”，可选择一个起始幕并可选“先打开页面”；保存后写入 `ctx.open("页面"); ctx.resume("幕")`。留空起始幕则写入 `ctx.resume()`，由播放器读取隐藏槽 continuation。自动演出在“页面结束后（关闭时）”同样可选“从指定幕开始 / 续接”或“从隐藏槽恢复”。

`ctx.resume(frame?)` 的目标用于重新开始或进入隐藏剧情，沿用隐藏槽的变量与历史；首次没有隐藏槽且未指定目标时由播放器拒绝，编辑器只写合法源码，不创建或修改隐藏槽，也不伪造隐藏状态。主菜单类流程可先打开 HUD：`ctx.open("hud"); ctx.resume("opening")`。末幕文字完成后的手动继续会触发一次 frameExit，补全不触发。

### 2.15 CG 专用资源与画廊（0.8.4）

用顶部 **导入 CG** 按钮或命令 **Kakera：导入 CG 专用资源** 导入 PNG/JPEG，生成 `<cg id="..." src="..."/>`。在故事检查器的“画面”区域选择“CG 专用画面”，保存后会生成 `<visual id="..." cg="..."/>`；CG 与背景、人物互斥，舞台预览显示完整 CG。

上游播放器会把所有 `<cg>` 自动加入画廊；UI 编辑器“CG 画廊”可编辑中文标题与初始解锁，并写显式 `<gallery><cg …/></gallery>`。未显式声明时标题默认为资源 ID、初始未解锁。UI 绑定可使用 `game.cgId`（当前幕 CG，普通幕为空）、`cg.total`、`cg.unlocked` 和 `cg.progress`。

解锁由作者决定：在现有 `game.enter` 中加入 `if (ctx.game.cgId) ctx.unlock(ctx.game.cgId);`，或在事件向导选择“解锁 CG”（留空生成 `ctx.unlock(ctx.game.cgId)`，也可指定 CG）。共享解锁在独立 `profile.json`，由匹配播放器维护；编辑器不写玩家档，也不在加载 CG 时自动解锁。

### 2.16 工作区界面（0.8.0）

顶部应用栏集中工程操作，左侧为工程概览、变量、注意事项与操作提示；中间是舞台和分镜图，右侧是可滚动的当前幕属性检查器，底部状态栏显示编辑状态、幕/变量/提示和当前路线。工程设置与图片工具改为右侧抽屉，可通过顶部“工程/图片”或侧栏按钮打开，Esc、遮罩或关闭按钮收起；未保存草稿仍保留。UI 编辑器使用页面/层级树、可缩放设计画布和按“布局/内容/交互”分组的属性面板；窄窗口会改为单列并保留全部入口。界面只改变布局与呈现，不改 XML/JS 内容或保存事务。流程图与 UI 设计画布保留真实指针拖动；宿主重绘丢失 pointer capture 时仍继续手势并在窗口级 pointerup 提交，避免幕布拖动卡住或回弹。

### 2.17 空窗口的资源管理器入口（0.11.2）

没有打开文件夹时，资源管理器的空状态会显示一段 Kakera 说明和“打开 Kakera 工程目录”按钮（`contributes.viewsWelcome` 的 `explorer` 条目，条件 `workspaceFolderCount == 0`；写成 `workbench.explorer.fileView` 时宿主不渲染该内容）。选中的目录必须自身含 `project.kakera-editor.json`（工程根）或 `story.xml`（内容根）；编辑器先按现有 `findRoot` 规则检查清单契约或内容根，再把这个目录作为本窗口的工作区文件夹重新载入，因此工程文件、工作区信任和 Kakera 侧栏都属于该工程。已有工作区时同一命令（**Kakera：打开游戏工程**）仍只打开该工程的分镜，不替换当前工作区文件夹。

### 2.18 原生工程侧栏、侧栏定位与短 ID（0.8.8 / 0.8.9）

Activity Bar 的 Kakera 视图改用原生 TreeView，按人物、美术资源、音频与字体、剧本、变量、JS 程序、界面分类；使用 VS Code ThemeIcon、计数描述、条目提示和原生右键菜单。分类支持新建人物/变量、导入立绘/Live2D/资源；条目支持人物重命名/删除、变量编辑/删除、幕新建后续/删除、资源引用、脚本/分镜/UI 打开。“界面”分类列出入口及全部 include 的 UI XML 文件：左键用可视化编辑器打开对应文件，右键“打开 UI 源码”打开原 XML。侧栏在工程激活时加载，并在文档或文件变化后刷新。

点击侧栏实际幕会打开/聚焦可视化编辑器并定位该幕；“剧本”改为“XML 文件 → 幕”两级，同一文件聚在同组。编辑器自动生成的幕、人物、立绘/模型资源、导入资源、visual/外观、UI 页面/控件、点九/图集和示例控件 ID 统一为 8 字节随机数的 16 位十六进制字符串（如 `9f2c...`），在对应命名空间冲突重试 64 次后才回退 UUID；已有手写/历史 ID 不批量改写。流程图多选与快捷键见 2.3。

## 3. UI 编辑器

### 3.1 打开与基本操作

点击工作台顶部“UI 编辑器”，或执行 **Kakera：打开 UI 编辑器**。左侧选择页面和控件，中间添加控件并拖动位置，右下角手柄调整大小；支持 8px 吸附、缩放、隐藏控件显示与方向键微调。右侧编辑文字/字号/颜色、尺寸、图片/点九/图集、数据绑定、事件及列表模板；“层级与顺序”可改父级、绘制顺序或移动到其他页面。属性点击保存，拖动/缩放松手后直接验证并保存，支持宿主撤销/重做。

可新增/删除页面、UI 变量与 CG 画廊条目，以及打开/关闭页面、推进/重开、选项、设置、演出/音效、CG 解锁、v0.9.1 的显式起始幕和 `present`/`resume` 交接事件；已有手写回调保留原文。UI 变量删除前检查控件绑定、窗口标题、已识别事件和脚本引用。入口和子文件均读取当前缓冲，标题绑定、纹理应用会写到实际声明文件。画布使用初始值和示例列表，不执行游戏脚本；剧情画面为占位，动画/滤镜、演出媒体和运行交互请试玩。详见 [UI 编辑器说明](16-ui-editor.zh-cn.md)。

### 3.2 按钮页面导航

在按钮属性的“按钮导航”选择“打开页面”并指定目标，或选择“关闭当前页面”，保存后写入原生 UI route；与交互事件互斥。已有 JS 保留。画布点击仍用于选中，“编辑目标页面”只切换设计页面；运行效果请试玩。

### 3.3 快捷弹窗、玩家快捷键与 HSL 配色（0.10.0，HSL 方形 0.10.1）

UI 编辑器左侧的“＋快捷弹窗”可在所选 UI 文件生成一页模态确认弹窗，填写标题、正文和确认/取消文字；确认动作可关闭页面、调用已有事件或自动生成 `ctx.quit()` 事件。事件向导新增“捕获键盘快捷键 / 取消捕获 / 修改快捷键绑定 / 恢复默认快捷键 / 保存颜色覆盖 / 恢复作者默认配色 / 退出游戏”，写入普通事件回调；绑定按 Ctrl、Alt、Shift 规范校验，留空写 `null`，`shortcuts.*` 可直接作为文本/布尔绑定并在画布预览默认标签。

“配色槽位”声明根级 `palette`，控件可用 `color-bind` 绑定 `colors.槽位` 或 UI string；HSL 选色器要求颜色值绑定 UI string；`alpha=false` 时至少 128×128，默认/`true` 至少 128×154（推荐 256×256 / 256×282），最多 8 个、不能放入 repeat；控件只绘制环/正方形/可选 alpha，没有内置预览或 HEX，预览与十六进制由 `color-bind`/`bind` 读取同一草稿独立组合；事件值使用规范 `#RRGGBBAA`。

添加选色器时留空更新事件会自动生成 `ctx.setUi("草稿", ctx.value)`；也可用新增的“设置 UI 变量”事件手动创建。palette 与 UI string 是引擎的两层设计：选色器只改草稿，正式控件用 `color-bind` 读取槽位，应用事件可选择固定颜色或读取 UI string 草稿（`ctx.colorPreference(槽位, ctx.ui.变量)`）。颜色属性使用文本加 HSL 色盘编辑；编辑器只写 XML/JS，`keybindings.json`、`ui-colors.json` 由匹配播放器维护，冻结代次和发行包也会排除这两个玩家偏好文件，静态画布不执行游戏脚本。契约细节与尺寸要求见 [22 引擎同步与版本增量](22-engine-sync-notes.zh-cn.md)。

### 3.4 演出与音效（0.6.2）

在 UI 编辑器顶部打开“演出与音效”，新建或选择声明。音效组可配置音频、角色、权重与启用状态；演出序列可顺序添加淡入淡出、视频和音效，设置跳过与完成后的页面导航。页面属性选择进入演出，按钮属性选择点击音效；“新建事件”也可创建播放器音效偏好开关事件。

声明写回实际 UI XML；已有 JS 保留，事件只追加白名单调用。每次保存先经匹配引擎检查，画布只显示静态布局，不模拟播放、随机选音或玩家偏好。玩家的 ui-audio.json 不进入内容快照和发行包。

### 3.5 组合标签与内置 tabs/分页器（0.11.2）

脚本在装配阶段用 `component.register("x-名字", { props, expand })` 注册加载期组合标签，UI XML 可直接写 `<x-名字 …/>`；展开结果仍是普通 UI 3 节点，事件、UI 变量与资源照旧由作者显式声明。编辑器静态读取可证明的顶层字面量注册（动态名/别名/函数内注册只给不确定诊断），校验标签名、prop 名与类型、必需属性、实例内 ID 与 `repeat.<节点ID>.*` 元数据绑定，并在设计画布把实例画成虚线占位——**不执行 expand**，最终语义仍由匹配引擎 `--check` 与真实试玩决定。UI 编辑器“插入组件”提供两个内置组件：标签页 `x-tabs`（按同工程其他非模态页面生成按钮、高亮变量与切换事件）和分页器 `x-pagination`（绑定带 `page-size`/`page-bind` 的 repeat，用 `ctx.repeats` 元数据更新页码）。插入时把注册写入已声明脚本（新工程模板带 `scripts/components.js`）、变量写入入口 `<variables>`、事件用 `event.register` 追加，不新建脚本文件。

### 3.6 模板常用页面（0.11.2）

新建工程模板现在带 7 个页面——`title`（初始标题页：开始/继续/读档/CG 画廊/退出）、`hud`（对话与选项）、`save`（200 个手动槽，每页 10 条）、`load`（自动档与手动槽两个标签页）、`gallery`（CG 画廊与进度，空画廊允许 0 条）、`confirm-save`/`confirm-quit`（覆盖与退出确认）。存档/读档/画廊都用 v0.11.2 的 repeat 分页；模板“开始新游戏”写无参 `ctx.restart()`，因为创建工程只重命名 frame ID、不改写 `scripts/ui.js`。整份模板通过真实引擎 `--check`（7 个 XML UI 页面、3 个 JS 文件）。

## 4. 图片工具

### 4.1 点九图

展开“图片工具 → 点九图”，打开已导入的普通 PNG/JPEG 或已有点九图，在图上拖出水平/垂直伸缩段和内容区，或输入精确像素。每轴支持 1–8 段，提供密度和目标尺寸拉伸预览。点击“保存点九图”生成真实 `.9.png`；可选择现有点九 UI 控件应用，或在页面添加示例控件。密度随所选 UI 控件保存。

### 4.2 图集

打开普通图片后框选、命名并编辑裁切区域，或输入格子大小、间隙和边距生成网格。选择区域后可应用到 image/panel/button 控件；也可勾选多张已导入图片并“生成并保存图集”，随后继续编辑区域。保存既有资源会保留 ID，并生成新文件保留原图；图片已变化时要求重新打开。操作与落地方案见[拖动连线与图片工具](14-graph-and-texture-tools.zh-cn.md)。

## 5. AI 拆幕

AI 是可选功能：执行 **Kakera：配置 AI 服务**，在普通原稿编辑器中选中纯文本，再执行 **Kakera：AI 拆幕提案**。请求前显示服务、模型和范围；当前仅发送选中文本，新增幕经差异审阅和引擎校验后应用，不自动连接到旧剧情入口。

## 6. 试玩、调试与构建

试玩从入口启动并显式选择起点，使用独立 save-dir；播放器独立开窗，只管理本插件启动的进程。调试提供 XML frame 断点、当前/候选只读变量与推进、选项选择，不提供 JS 行级调试。构建选择内容根之外的发行父目录，先审阅实际包内文件清单，再生成独立游戏目录与构建报告；不自动上传。

### 6.1 Live2D

Live2D 未配置 Core 时会明确显示并使用静态回退。执行 **Kakera：配置 Live2D Cubism Core** 可以选择受信任的本机 DLL 用于原生校验/试玩；Core 不会自动分发。含模型的游戏构建目前提供静态回退版，通过生成的“开始游戏.cmd”运行。

## 7. 源码映射与只读限制

### 7.1 JS/XML 实时同步

工作台根据当前 JS/XML 编辑缓冲自动同步：注释、CRLF、单双引号、简写箭头、普通函数、上下文参数名、固定字符串常量，以及跨脚本/跨章节的幕 ID 和名称引用都参与识别。修改已识别路线只补丁对应语法节点，保留其他手写代码；“查看此幕逻辑”可跳到注册位置。界面显示可编辑幕数和此幕受限的具体原因，JS 语法修复后自动恢复映射。

受限 if/else 和三元表达式的类型化条件与固定目标可实时映射并编辑；共享函数、自定义判断或计算目标保留原文并显示候选/动态节点。其他可识别幕仍可新增和改线，当前幕的台词/人物/画面也可保存。动态注册、注册对象别名或重复注册会使受影响范围只读；无法确定全部入边时暂停自动删除。静态分析不执行游戏 JS，也不声称能够预测任意代码的运行结果。详细规则见 [JS/XML 同步映射](13-live-logic-mapping.zh-cn.md)。

### 7.2 未信任工作区与恢复

未信任工作区只能只读查看。恢复入口为 **Kakera：检查编辑恢复记录**，检测到后续修改时拒绝覆盖，需手工合并。

### 7.3 静态画布的边界

静态画布只显示初值和默认绑定示例，不执行脚本、不模拟捕获/拖拽/焦点、不执行页面交接或玩家偏好写入。真实按键、冲突、焦点清理、偏好的原子保存和回滚由匹配播放器验收；详见 [UI 编辑器说明](16-ui-editor.zh-cn.md)、[可视化编辑器使用说明](18-visual-editor-guide.zh-cn.md) 和 [实现记录](12-implementation-status.zh-cn.md)。
