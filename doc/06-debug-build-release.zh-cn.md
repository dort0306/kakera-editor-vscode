# 06 调试与构建发布

基线更新为 v0.8.3。播放器已有帧级调试/状态接口和发布依赖选择；VS Code 插件、DAP 适配、可视编译和构建 UI 仍待实现。

## 1. 预览与真实调试

| 模式 | 内容 | 状态 |
| --- | --- | --- |
| 单幕构图 | 显示完整 Frame 的背景/人物/台词 | 编辑器待实现，不是可保存的剧情会话 |
| 真实试玩 | 从入口走 Controller/QuickJS、媒体/历史 | 已有外部播放器，插件需封装 |
| 帧级调试 | 状态、暂停/继续、断点、逐步推进/选择 | v0.8.3 已实现，详见 [10](10-player-debug-api.zh-cn.md) |
| 高级调试 | 条件断点、推送事件、源码指纹、跨代次替换、JS 行级步进 | 后续能力，当前不提供 |

插件使用明确 --project、隔离 --save-dir、loopback --debug-listen 和令牌文件启动进程；令牌不是 AI 服务密钥。当前状态通过 JSON Lines 查询，控制命令使用最新 state_revision；适配器将帧/XML 行映射到 IDE 断点，不能假装引擎协议已经是 DAP。

初始暂停。进入断点前候选条件、变量更新、game.enter 与媒体必须全部验证成功，随后保存完整候选；旧 Session/画面/声音及 UI 不提交。advance 可提交候选并保持暂停，resume 提交后运行。隐藏选项、坏目标和失败计划沿用原事务回滚。

正常剧情输入在调试暂停时阻挡；菜单/提示/自动存档等待仍阻挡调试步进。断线后可重连，不能把超时当作命令未执行；先查询状态，按相同请求 id/字节重发避免重复推进。调试默认关闭自动保存，正式与测试数据仍必须隔离。

## 2. 源码、代次与路线

编辑器生成完整冻结试玩代次，不能监控半写入的多文件源事务。当前暂停期间延后热更；继续原候选后再走普通兼容性/历史验证。更精确的受控代次替换和 sourceFingerprint 协议未实现。

单幕构图预览不允许直接修改 Session.frame_id 或写假档。从入口记录 Advance/Choose 序列与变量/位置断言，复用实际控制器重放到目标；没有合法路线时只做构图/离线条件预览。运行变量面板先只读。

EditorSourceMap 将生成 XML/JS 行列映射到幕/选项/原稿段落，叠加现有 story_chain 源位置。动态路由只显示运行时观察边，Opaque JS 保留原始栈与代码，不宣称穷举。

## 3. 发布选择与清单

v0.8.3 的真实 kakera-pack 使用记录型 ContentSource 做依赖发现，包含 XML 章节、JS、已声明并准备的图片/字体/音频/视频/模型及辅助文件；视频通过流式 open 记录，不整文件读入 Vec。默认附带 assets/licenses 与 licenses 中的普通文件。

额外发行文件通过游戏根可选 kakera.package.json 显式列出：schema 为 1，include 为游戏内相对文件名数组，不接受目录/通配/越界/重复/缺失项。清单最多 1MiB；清单本身不进入 KPAK。未引用普通文件、编辑器索引/模型权重不再因位于根内就自动加入。

显式 include 表示作者确实要求加入该文件，不是自动隐私分类器；错误 include 仍可能把私有文件加入，所以发行清单检查保留。原始 Snapshot/StagedProject 容器 API 仍可用于通用数据，工程监控也不按引用裁剪；不要绕过 CLI 策略后声称有同样保证。

## 4. 构建流水线

1. 固定已提交 revision；验证未保存缓冲时明确其版本，先导出到纯游戏根，保留稳定 ID。
2. 验证 XML/JS、完整资源/Core 和选定测试路线；说明动态分支未证明范围。
3. 检查依赖/许可证/显式 include，阻止未解决占位、错误引用、预算超限和不当私有文件。
4. 调用匹配 kakera-pack，默认 KPAK 2，小包可显式 1。选中文件/清单改变时拒绝提交，候选独立重载与块校验成功后原子输出；输出须在工程根外。
5. 对包运行完整 --check，组装匹配播放器、包外受信任 Core（需要时）、字体/模型/依赖许可证和启动说明。
6. 从源码/SDK/AI 服务之外检查与试玩，游戏运行不得依赖作者模型服务、缓存或开发机字体。
7. 记录源、模板、工具、服务提案来源、content-version、ID 策略、文件/包哈希、测试与许可证；成功后提交新发行目录，失败保留旧产物。

现有 package.ps1 仍会构建 Rust 工具并复制固定 runtime Core/许可证。最终插件发行器需随附匹配工具并显式选择宿主 Core，不要求作者有 cargo/SDK。公开上传不是打包任务的自动步骤。

## 5. 门禁与未实现范围

语法/资源/类型/入口错误、未解决占位、预算/块校验/许可证缺失都阻止完整交付；未覆盖动态分支单独报告。改变 ID、变量契约或重新生成缺省 UUID 必须显示旧档风险并决定 content-version。

v0.8.3 不提供任意跳转/改变量/eval、正式槽位注入、通用 JSON 诊断、推送事件、网络公网调试监听或 JS 行级调试。AI HTTP API 客户端仍是编辑器待实现工作。


v0.8.3 附加清单也拒绝保留用户文件/目录及临时文件（如 settings.json、read.json、slot-/auto- JSON、saves/、target/、.git/、*.tmp）；不能用显式 include 绕过原有排除规则。
