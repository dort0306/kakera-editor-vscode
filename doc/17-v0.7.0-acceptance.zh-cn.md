### A-01：缺失页面引用没有静态诊断

优先级 P2。在有效 UI fixture 的已声明脚本中追加：

```js
on.screenOpen("missing.page", ctx => {});
on.ui("handoff", ctx => ctx.present("missing.page"));
```

页面 `missing.page` 不存在。`analyzeLogic` 收集到 `references.screens`，但返回空 `issues`；`readUiDesign` 返回空 `warnings`。目前 `packages/source/src/logic.ts` 只收集页面名，`packages/source/src/ui-source.ts` 未补做这些引用的页面存在性诊断。该结果不符合实现记录中“动态或缺失目标给出诊断”的完整表述。

在补齐模板必需的 routes.js 后分别调用真实播放器 `--check --no-audio --no-live2d`：缺失页面的 `screenOpen` 注册退出 1，提示“生命周期页面不存在”；只注册包含错误 `present` 目标的普通 UI 回调退出 0。后者没有执行回调，不能把通过启动检查当作交接目标可用的证明。本轮没有执行该错误交接，不推断其运行结果。

复现脚本与输出：`.test-work/acceptance-0.7.0/probe.ts`、`probe.log`、`probe-engine.mjs`、`probe-engine.log`。建议补充基于实际 UI 页面集合的直接静态引用校验、可定位诊断及对应测试，并统一动态页面目标的提示。修复后需重新验收本项。
